# Demo script — target 2 minutes 40 seconds

Record the verified final build. Use captions large enough to read. Say the provider and model aloud. Do not include credentials, copyrighted music, or unsupported claims. The recording may use edits to remove waiting, but label recorded live evidence and injected faults accurately; do not portray a saved replay as a fresh call.

| Time | On screen | Suggested narration |
|---|---|---|
| 0:00–0:15 | Release decision and local issue board | “A passing agent test only helps if it describes the configuration that actually acts. ReleaseProof makes that connection visible and enforceable.” |
| 0:15–0:35 | Candidate, model, source badge, real completed triage attempt | “This issue-triage agent uses NVIDIA Nemotron through Nebius Token Factory. It labels an issue, routes it, and prepares a draft. These are synthetic issues; this evidence is [live / recorded live / fixture—use the actual mode].” |
| 0:35–0:57 | Qualification results and a case trace | “We test the exact prompt, tools, policy, and model. Here are the actual outcomes, including failures and human-review cases. A small benchmark is evidence for this workflow, not a claim of general safety.” |
| 0:57–1:17 | Budget reservation, observed usage, protected reserve | “Before a call, we reserve its worst-case allowance. We reconcile observed token usage and protect capacity for validation and recovery. Qualification and monitoring have a cost too; these figures include that overhead.” |
| 1:17–1:37 | Promote and execute, then change a contract field | “Promotion is explicit. Now I change the [prompt/tool/policy]. The exact contract fingerprint changes. The previous pass cannot authorize this version. Hashrope preserves the versioned execution evidence.” |
| 1:37–1:52 | Denied action with reason; unchanged board | “The server refuses the action, rather than just showing a warning. Pollard enforces the execution decision. We need current evidence to proceed.” |
| 1:52–2:15 | Requalified state, labelled injected-drift canary, hold | “This is a controlled injected-drift experiment, not an incident observed at Nebius. Epicormic compares repeated behavior. The resulting hold prevents future actions; it does not undo completed work.” |
| 2:15–2:30 | Mitigation, stale fallback denial or valid fallback; evidence export | “Mitigation still needs a valid contract. A fallback does not revive stale approval. The evidence packet records which release was tested, what happened, and why the next action was allowed or refused.” |
| 2:30–2:40 | Final product view and links | “ReleaseProof: a budgeted, reviewable path from an agent candidate to permission to act. The runnable code and demo are linked in our submission.” |

## Recording gates

- Show an actual live Nebius/NVIDIA run or its clearly labelled recorded evidence. Fixture-only footage does not establish the required integration.
- If no candidate passes, show the honest hold and failure analysis; do not fake a passing result or promise promotion that did not occur.
- Do not say “automatic rollback” for a future-action hold or configuration selection. No external issue tracker is being changed.
- Keep source badges, sample counts, and cost basis readable. Omit any metric that has not been measured.
- Export the evidence before recording. Upload the public YouTube video early and verify it in a signed-out browser.
